# 라벨 기준 — 메일 판단 정확도 측정

정답은 사람이 정합니다. 이 문서는 **무엇을 정답이라 부를지**를 먼저 고정합니다. 기준이 측정
뒤에 정해지면 그 수치는 아무것도 증명하지 못하기 때문입니다.

라벨을 다는 순서도 정해져 있습니다. **모델 답을 보기 전에** 초안을 답니다(블라인드). 초안은
Claude가 달고, 사람이 검수해 확정합니다. 두 사람의 판단이 갈린 항목은 지표에서 따로 셉니다.

---

## 네 가지 질문

### 1. `needs_reply` — 내가 답장을 써야 하는가 (예/아니오)

"읽어야 하는가"가 아니라 **"내가 글을 써서 보내야 하는가"** 입니다.

- **예**: 상대가 나에게 물었다 / 일정·참석·수락 여부를 회신해야 한다 / 내가 보낸 문의의 답이
  왔고 이어서 말해야 한다 / 사람이 직접 쓴 메일이고 답이 없으면 상대가 기다린다
- **아니오**: 단체 공지·뉴스레터·모집 안내 / 자동 발송(인증번호, 로그인 알림, 빌드 실패) /
  "회신 불필요"라고 적혀 있다 / 광고·프로모션

애매한 기준 하나: **보낸 사람이 내 답을 기다리고 있는가.** 기다리지 않으면 아니오입니다.

### 2. `action_elsewhere` — 할 일이 답장이 아니라 다른 곳에 있는가 (예/아니오)

- **예**: 구글폼·신청 링크·포털 로그인·버튼 클릭으로 처리하는 일. 답장으로 신청되지 않는다
- **아니오**: 그런 링크가 없거나, 링크가 있어도 회신으로 처리하는 일

`needs_reply`와 독립입니다. 둘 다 "아니오"인 공지가 가장 흔합니다.

### 3. `needs_human` — 사람이 직접 써야 하는가 (예/아니오)

도구가 초안을 만들어 주면 **곤란한** 건에 예입니다.

- **예**: 돈·계약·환불·법적 책임 / 거절·사과·항의 대응 / 내 개인 사정이나 판단이 들어가야 하는
  답(지원 의사, 일정 조율의 실제 가능 여부) / 상대가 화가 나 있다
- **아니오**: 사실 확인·접수 확인·간단한 일정 회신처럼 초안이 도움이 되는 건

`needs_reply`가 아니오면 이 값은 의미가 없으므로 비워 둡니다(`null`).

### 4. `urgency` — 언제까지 (0~3)

| 값 | 뜻 | 예 |
|---|---|---|
| 0 | 기한 없음 | 뉴스레터, 일반 공지 |
| 1 | 이번 주 안 | 접수 확인, 여유 있는 안내 |
| 2 | 오늘~내일 | 마감 임박, 내일 행사, 일정 조율 회신 |
| 3 | 지금 | 보안 경고, 오늘 마감, 즉시 확인 요구 |

**메일에 적힌 날짜 기준**으로 매깁니다. 지금 읽는 시점이 아니라 **받은 시점**에서 얼마나
급했는가입니다(지난 메일이라고 0을 주지 않습니다).

---

## 두 종류의 정답

| 출처 | 표시 | 뜻 |
|---|---|---|
| 사람의 검수 | `gold` | 이 문서 기준으로 사람이 확정한 값 |
| 실제 행동 | `replied_later` | 이 메일에 **실제로 답장했다**. 답장 직전 시점으로 잘라 저장한 스레드 |

`replied_later`는 추측이 아니라 기록입니다. `needs_reply`의 정답과 어긋나면(답장했지만 굳이
안 해도 됐다 등) 사람의 검수가 이깁니다 — 다만 그런 건수는 리포트에 따로 적습니다.

## 하지 않는 것

- 모델 답을 보고 라벨을 고치지 않습니다. 검수 화면에 모델 답은 나오지 않습니다.
- 판단이 서지 않으면 `?`로 두고 지표에서 제외합니다. 억지로 채운 라벨이 제일 해롭습니다.
- 메일 본문은 저장소에 올리지 않습니다(`eval/data/`는 git이 무시합니다).
